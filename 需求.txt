# CMD 多窗口管理工具 - 需求文档

**版本**：1.0  
**目标平台**：Windows (兼容 Qt 5.15+/6.x)  
**开发框架**：C++ / Qt  
**文档日期**：2026-05-09  

---

## 1. 项目概述

### 1.1 背景
开发者在日常工作中经常需要同时开启多个命令提示符（CMD）窗口，例如：运行开发服务器、监控日志、执行编译任务、持续 ping 等。原生 CMD 窗口采用多实例独立管理方式，切换窗口、查看输出、批量关闭等操作繁琐低效。

### 1.2 目标
开发一款基于 Qt 的图形化管理工具，提供统一的界面来管理多个 CMD 会话。用户可以在左侧列表中查看所有活动会话，右侧内嵌终端区域实时显示当前会话的输出，并支持发送命令、新建/关闭会话、重命名等操作。从而提升多窗口管理效率。

### 1.3 范围
- 本工具专注于 CMD (cmd.exe) 进程的管理，不包含 PowerShell 或其他 shell 的官方支持（但架构应具备可扩展性）。
- 仅支持 Windows 平台（利用 Win32 API 实现进程隐藏/激活等）。
- 不替换系统本身的 CMD，而是作为 CMD 进程的外壳控制器。

---

## 2. 用户角色
- **普通用户**：开发人员、运维人员、学生等需要频繁使用 CMD 窗口的用户。

## 3. 功能需求

### 3.1 会话管理（左侧列表）
| 编号 | 功能 | 描述 |
|------|------|------|
| FR-01 | 显示会话列表 | 左侧面板以列表形式展示所有被管理的 CMD 会话，每个条目显示：会话名称（用户自定义或自动生成）、PID、状态（活跃/空闲）、可选图标。 |
| FR-02 | 新建会话 | 用户可通过按钮或菜单新建一个 CMD 会话。新建时需要指定初始工作目录（可选），并自动生成默认名称（如 “CMD-1”）。新建后该会话自动加入列表并切换为当前活动会话。 |
| FR-03 | 切换会话 | 点击左侧任意会话条目，右侧终端区域立即切换为该会话的输出视图，同时顶部标题栏显示当前会话名称和 PID。 |
| FR-04 | 关闭会话 | 每个会话条目上提供关闭按钮（或右键菜单）。关闭时向对应的 CMD 进程发送 WM_CLOSE 消息或终止进程，并从列表中移除。关闭前需确认（可配置）。 |
| FR-05 | 重命名会话 | 支持右键菜单或双击会话名称进行重命名，不影响底层 CMD 进程。名称仅用于用户识别，持久化存储（可选）。 |
| FR-06 | 会话搜索/筛选 | 在左侧列表上方提供搜索框，可根据会话名称或 PID 实时过滤列表。 |

### 3.2 终端显示（右侧区域）
| 编号 | 功能 | 描述 |
|------|------|------|
| FR-07 | 实时输出显示 | 右侧区域以类似终端的风格（黑底彩色文字）实时显示当前 CMD 进程的标准输出和标准错误输出。支持 ANSI 转义序列的基本解析（如颜色、光标移动可选）。 |
| FR-08 | 滚动与缓冲 | 支持鼠标滚轮滚动查看历史输出，缓冲区大小可配置（默认 10000 行）。 |
| FR-09 | 用户输入 | 底部提供输入行，用户键入命令后按回车或点击“发送”按钮，将命令写入对应的 CMD 进程的标准输入。支持命令历史（上/下键）。 |
| FR-10 | 清屏 | 提供清屏按钮或支持 `cls` 命令（与 CMD 内部命令行为一致）。 |
| FR-11 | 复制/粘贴 | 支持在终端区域选择文本并复制（Ctrl+C 或右键菜单），支持从剪贴板粘贴命令到输入行（Ctrl+V）。 |
| FR-12 | 查找 | 支持在当前会话输出中查找关键字（Ctrl+F），高亮显示。 |

### 3.3 全局操作
| 编号 | 功能 | 描述 |
|------|------|------|
| FR-13 | 激活窗口 | 当工具主窗口最小化或处于后台时，可通过系统托盘图标或全局快捷键激活。 |
| FR-14 | 批量操作 | 支持多选会话并批量关闭、批量发送命令（可选高级功能）。 |
| FR-15 | 保存/恢复布局 | 保存当前所有会话的配置（工作目录、会话名称、窗口大小/位置），下次启动时自动恢复。 |
| FR-16 | 设置界面 | 提供设置对话框，可配置：默认工作目录、缓冲区大小、字体/颜色主题、是否关闭时确认、是否开机启动等。 |

### 3.4 与 CMD 进程的交互（技术实现细节）
| 编号 | 功能 | 描述 |
|------|------|------|
| FR-17 | 进程创建 | 使用 `QProcess` 或 `CreateProcess` 创建 `cmd.exe` 进程，重定向标准输入、输出、错误管道。为了获得类似终端的体验，需要设置 `CREATE_NO_WINDOW` 标志以避免显示额外控制台窗口；或通过 `STARTF_USESTDHANDLES` 设置管道。 |
| FR-18 | 伪终端支持（推荐） | 为了正确处理交互式命令（如 `ping -t`、`npm run dev` 等需要实时刷新的场景），建议使用 Windows 伪控制台（ConPTY）API，实现真正的终端模拟。若 ConPTY 不可用（Win10 版本 1809 以前），降级使用管道模拟。 |
| FR-19 | 窗口激活 | 虽然工具内嵌了终端显示，但为用户提供“在新窗口打开”的选项（即分离显示原生 CMD 窗口）。同时提供“激活原生窗口”功能，通过 `FindWindow` 和 `SetForegroundWindow` 定位并置顶对应的 CMD 窗口（需要记录窗口句柄）。 |
| FR-20 | 进程监控 | 轮询或通过进程句柄等待，当 CMD 进程意外退出时，自动标记会话为“已终止”，并在终端区域显示退出信息；用户可选择重新启动或关闭该会话。 |

## 4. 非功能需求

### 4.1 性能
- 同时管理 20 个以上 CMD 会话时，界面应保持流畅，无明显卡顿。
- 终端每秒更新应不低于 30 行输出时界面不冻结（使用异步 I/O 和线程隔离）。

### 4.2 易用性
- 界面布局清晰，左侧列表可折叠/调整宽度，终端区域字体大小可缩放（Ctrl+滚轮）。
- 快捷键支持：
  - `Ctrl+T`：新建会话
  - `Ctrl+W`：关闭当前会话
  - `Ctrl+Tab` / `Ctrl+Shift+Tab`：切换会话
  - `Ctrl+Shift+C`：复制终端选中文本
  - `Ctrl+Shift+V`：粘贴到输入行

### 4.3 可维护性与扩展性
- 代码采用模块化设计：`SessionManager`（会话管理）、`TerminalWidget`（终端显示）、`ProcessHandler`（进程通信）、`SettingsManager`（配置）。
- 预留其他 shell（PowerShell、WSL）的接入点。

### 4.4 稳定性
- 进程意外崩溃不应导致工具整体崩溃。
- 管道读写错误应能自动重建会话。

### 4.5 兼容性
- 支持 Windows 10/11（x64），建议 Windows 10 版本 1809+ 以获得最佳 ConPTY 支持。
- Qt 版本：5.15 LTS 或 6.2+（需支持 Win32 API 和 ConPTY）。

## 6. 技术架构建议（Qt + C++）

### 6.1 模块划分
- **MainWindow**：负责整体布局，菜单栏，工具栏，状态栏。
- **SessionManager**：单例，管理所有 Session 对象（创建、销毁、切换、持久化）。
- **Session**：封装一个 CMD 进程实例，包含 QProcess 或 ConPTY 句柄、输出缓冲区、会话元数据（名称、PID、工作目录等）。
- **TerminalWidget**：自定义 QWidget，使用 QTextEdit 或 QPlainTextEdit 显示终端输出，支持 ANSI 转义序列解析（可使用第三方库如 `ansiescapecode` 或自己实现颜色解析）。
- **InputLine**：QLineEdit 配合历史记录。
- **SettingsDialog**：配置界面。

### 6.2 关键技术点
- **ConPTY 使用**：通过 `CreatePseudoConsole`、`ResizePseudoConsole` 等 API 创建伪终端，并将其句柄与 Qt 的 QWinEventNotifier 结合，实现异步读取。
- **管道通信**：若不使用 ConPTY，则使用 `QProcess::setProcessChannelMode(QProcess::MergedChannels)` 并连接 `readyReadStandardOutput` 信号。
- **异步处理**：终端输出读取应放在工作线程或使用 `QSocketNotifier`，避免阻塞 UI。
- **配置存储**：使用 `QSettings`（Windows 注册表或 INI 文件）保存会话列表、窗口布局、设置项。

### 6.3 第三方库
- **QDarkStyleSheet**：提供深色主题外观。
- **qtermwidget**（可选）：如果不想自己实现终端模拟，可集成 KDE 的 `qtermwidget`，但需要在 Windows 上编译。
- **ansicolor**：轻量级 ANSI 转义序列解析器（可自己实现基础颜色支持）。

## 7. 验收标准
1. 能够创建至少 10 个 CMD 会话，每个会话独立运行，输出正确显示在对应终端区域。
2. 左侧列表点击切换时，右侧终端内容即时更新到该会话的最新输出。
3. 用户可以在输入行发送命令（如 `dir`, `echo hello`），并能看到命令执行结果。
4. 关闭会话时，对应的 cmd.exe 进程被终止。
5. 程序关闭后再打开，之前的会话列表和工作目录能够恢复（自动恢复设置）。
6. 长时间运行（例如 24 小时）无内存泄漏或崩溃。
7. 支持基本的 ANSI 颜色输出（如 `npm run dev` 的彩色日志）。

## 8. 风险与应对
| 风险 | 应对措施 |
|------|----------|
| ConPTY 在旧版 Windows 不可用 | 检测 ConPTY 可用性，若不可用则回退到简单 QProcess 管道模式，并提示用户升级 Windows 版本以获得最佳体验。 |
| 某些交互式程序（如 `python` REPL）无法正常工作 | 对于需要原始终端输入的程序，提供“在原生窗口打开”选项，直接显示 CMD 原生窗口，工具仅作为启动器。 |
| 进程退出后管道仍残留 | 使用 `QProcess::finished` 信号及时清理会话资源，并通知 UI 标记为“已终止”。 |
| 大量输出导致界面卡顿 | 使用分批次更新、限制缓冲区大小、延迟渲染（如 50ms 合并更新）等优化手段。 |
